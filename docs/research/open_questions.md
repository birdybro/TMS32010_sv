# Open architecture questions

Open questions are not implementation permissions. Provisional choices require
a targeted test and must retain their confidence label.

| ID | Question | Status / competing hypotheses | Evidence needed | Hard Drivin' impact |
|---|---|---|---|---|
| OQ-001 | Can external cycles be lengthened on a part with no READY pin? | UNKNOWN: clock-input pause may be legal, or memories must always meet fixed AC limits | TI clock-generator and AC sections; hardware measurement if silent | program RAM and wrapper clock-enable design |
| OQ-002 | What is observed for original-TMS32010 data addresses `0x90`–`0xff`? | UNKNOWN: alias, open/internal value, or undocumented decode | original data-sheet decode detail or physical chip | likely low unless software accesses it |
| OQ-003 | What value does `SST` produce in reserved bit 1? | BLOCKED: SPRU001B Figure 2-7 marks bit 1 “don't care,” its LST page and SPRU002B show one, while SPRU013 shows zero; bits 12:9 and 7:2 are consistently one | original-part erratum or a physical TMS32010 store-status measurement across relevant mask revisions | possible context-save code that inspects the complete saved word |
| OQ-004 | What is the exact interrupt-recognition and vector-fetch cycle trace? | RESEARCHING: falling-CLKOUT pin sample and pulse limits verified; vector-fetch phases untranscribed | Figure 2-11 plus a minimal program/bus trace; physical trace if ambiguous | low if board INT is tied inactive |
| OQ-005 | Is Hard Drivin' TMS32010 `INT` tied inactive, and what net is `PR1`? | RESEARCHING: schematic appears to tie pin to a rail; MAME models no DSP interrupt source | full net-name/title-block review and board BOM/netlist | determines interrupt integration |
| OQ-006 | Which edge completes reset and starts the first address-0 fetch? | RESOLVED_PRIMARY: recognized reset changes are synchronized to falling CLKOUT; PC/address clears after the next complete cycle, and release resumes after one complete cycle with address 0 then 1 | Appendix A reset timing, data-sheet p. 19 (PDF p. 375); directed RTL phase test passes | reset/halt release trace |
| OQ-007 | What are exact taken/untaken branch prefetch and address traces? | RESEARCHING; both are listed as two cycles | individual instruction diagrams and hardware trace if needed | program trace alignment |
| OQ-008 | Does any mask revision materially differ? | UNKNOWN | TI errata/mask notices or measured devices | release qualification |
| OQ-009 | Is a lawful, automatable modern TMS32010 assembler available? | RESEARCHING; no qualified candidate yet | license/source/encoding audit | local test-program workflow |
| OQ-010 | What does an indirect control field do when increment and decrement bits are both one? | UNKNOWN: TI defines each bit separately but offers no syntax, example, or combined result; current decode rejects it | explicit TI reserved-encoding statement or physical opcode test | malformed code only; ordinary Hard Drivin' binaries are unlikely to emit it |
| OQ-011 | Does original-TMS32010 `ADDH` affect `OV`/`OVM`, and if saturated does its low accumulator half change? | UNKNOWN: original and SPRU013 pages omit status behavior; C14/E14 says `OV`/`OVM` apply while the low half is unaffected; MAME implements high-half-only saturation as an inference | original-part erratum, authoritative microarchitecture detail, or physical TMS32010 boundary tests | unknown until Hard Drivin' opcode/OVM usage is inspected |
| OQ-012 | Does physical reset preserve every state element not named by TI, including `OV`, `ACC`, ARs, ARP, and DP? | UNKNOWN: TI explicitly changes PC/interrupt state and preserves OVM but does not characterize the other registers; current RTL assigns them no reset value and therefore retains prior FPGA state | explicit TI reset-state statement, die/reset-network evidence, or before/after physical-chip tests | software may inspect retained arithmetic/address state after host reset |
| OQ-013 | Does original-TMS32010 `ABS` set sticky `OV` when negating `0x80000000`? | UNKNOWN: original-part instruction pages define the OVM-dependent result but omit the OV side effect; the C14/E14 variant explicitly says ABS affects OV, while pinned MAME leaves OV unchanged | original-part erratum or microarchitecture detail, or a physical test beginning with OV clear and observing status through `SST` after the boundary case | relevant only if code takes this boundary absolute value and later tests or saves OV |
| OQ-014 | What does `DMOV`/`LTD` do when the next-higher destination is outside the original 144-word RAM, especially source `0x8f` and destination `0x90`? | UNKNOWN: TI defines an unconditional copy to `dma+1` but does not define absent-location decode, aliasing, write suppression, or whether the other parallel LTD effects complete | original data-RAM decode detail, erratum, or a physical-chip program that observes T/ACC/status after the boundary move | likely low unless software places a delay line at the final implemented word |
| OQ-015 | After indirect `LST`, does an encoded next-ARP field or data-word bit 8 determine final `ARP`? | PROVISIONAL: original TMS32010 guides expose the optional field while also saying the memory word loads ARP, but do not state precedence; later TI SPRU012 explicitly says the field is ignored, and pinned MAME independently agrees | original-part erratum, microarchitecture description, or physical TMS32010 test with conflicting values | context restore can select the wrong AR if the provisional precedence is wrong |
| OQ-016 | What exact external program-address and `MEN` sequence occurs during the second cycle of single-word `PUSH` and `POP`? | RESEARCHING: original instruction pages and Table 3-2 establish one word/two cycles and the specified stack/ACC effects, but no located waveform identifies whether the next word is prefetched, held, or fetched only after an inactive extra cycle | original TI pipeline/control timing diagram, development-system cycle trace, or physical logic-analyzer capture around minimal PUSH/POP programs | blocks honest native-phase RTL qualification even though model/tool and stack-state research can proceed |
